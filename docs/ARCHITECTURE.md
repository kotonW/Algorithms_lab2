## 4. Доменная модель

### 4.1. Ковёр Серпинского

```
Fill(x, y, size, level):
    if level == 0 или size <= 1:  закрасить квадрат; return
    child = size / 3
    для 9 частей, кроме центральной: Fill(...)
```

Ключевое отличие от «наивной» реализации: рекурсия не спускается до уровня 0, если часть уже стала размером с пиксель. Это делает стоимость `O(число пикселей)`, а не `O(8^n)`. Благодаря этому глубина 8 строится за ~110 мс при растре 2187².

Характеристики (используются в UI и в тестах):

| Величина                | Формула                  |
|-------------------------|--------------------------|
| Число клеток            | `8^n`                    |
| Площадь фрактала        | `(8/9)^n`                |
| Площадь «дыр»           | `1 − (8/9)^n`            |
| Фрактальная размерность | `log 8 / log 3 ≈ 1,8928` |

В правой панели дополнительно показываются разрешение растра, фактическая доля закрашенных пикселей и время построения.

> При проектировании в первой версии документа площадь была записана как `1 − (8/9)^n` — это площадь вырезанных дыр, а не самого фрактала. Ошибку поймал тест, сравнивший теоретическую долю с фактической долей закрашенных пикселей.

### 4.2. Ханойские башни

`HanoiSolver` умеет строить список ходов двумя способами: рекурсией (`Solve`) и явным стеком (`SolveWithStack`), результаты обязаны совпадать ход в ход — это проверяется тестом и кнопкой «Сравнить рекурсию и стек» в интерфейсе (замер времени обоих способов и проверка совпадения). `HanoiPuzzle` хранит состояние стержней (снизу вверх), умеет шагать вперёд, назад и переходить к любому ходу; индекс за пределами диапазона прижимается к нему, поэтому «шаг назад» в самом начале просто ничего не делает. Общее число ходов — `2^n − 1`.

### 4.3. Перебор всех перестановок

`PermutationGenerator` — рекурсивный перебор с возвратом: элемент фиксируется на текущей позиции, хвост перебирается рекурсивно; всего получается `n!` результатов. Рекурсия периодически проверяет `CancellationToken`, поэтому замер можно прервать даже при n = 15, не дожидаясь конца текущего прогона.

`AllPermutationsAlgorithm` — обёртка над генератором, реализующая `ITimedAlgorithm<int, long>`: на вход получает `n`, на выходе отдаёт число найденных перестановок (оно используется как проверка корректности: `RunOnce(n)` должен вернуть `n!`). Теоретическая оценка сложности — `O(n!)`.

### 4.4. Числа Каталана

Папка `Domain/Catalan`:

- `NaiveCatalanAlgorithm` — наивная реализация вычисления числа Каталана `C(n)`; реализует `ITimedAlgorithm`, то есть ничего не знает о замерах;
- `CatalanResult` — результат вычисления;
- `CatalanNumbers` — вспомогательный тип для чисел Каталана.

Определения, на которые опирается задача: `C(n) = (2n)! / ((n+1)!·n!)` и рекуррентное соотношение `C(n+1) = Σ C(i)·C(n−i)` по `i = 0..n`.

`ITimedAlgorithm<TInput, TResult>` (папка `Domain/Benchmarks`) описывает «чистый» алгоритм: имя и `Execute(input)`. Он ничего не знает ни о `Stopwatch`, ни о графиках — вся инфраструктура замеров лежит выше, в `Application` (см. §10).

## 5. Рендеринг

### 5.1. Почему растровый режим

Наивная отрисовка полигонами даёт `8^n` объектов: 262 144 при глубине 6 и 16,7 млн при 8. Граф плюмбалов в ScottPlot перерисовывается на каждый кадр, поэтому пан и зум превратились бы в слайд-шоу. Вместо этого:

1. Домен строит `GrayRaster` — `byte[]` с 0/255, без зависимостей от графики.
2. `RasterImageFactory` переводит его в `byte[высота, ширина, 3]` с цветами палитры.
3. `SierpinskiPlotRenderer` создаёт `ScottPlot.Image` и один плюмбал `ImageRect`.
4. В графе всегда **один** объект, независимо от глубины.

Разрешение растра отвязано от глубины: `RenderLimits.PixelSideFor` даёт `3^depth`, но не меньше 243 и не больше 2187 пикселей (2187² ≈ 4,8 МБ). Восьмой уровень при таком растре мельче пикселя, поэтому максимальная глубина ограничена семью: `3^7 = 2187` — ровно сторона растра, и теоретическая площадь совпадает с фактической долей пикселей.

### 5.2. Пропорции

`ImageRect` растягивается на прямоугольник `(0,0)–(1,1)`, а окно не квадратное. Чтобы фрактал не искажался, рендерер получает соотношение сторон области рисования и расширяет диапазон по более «длинной» оси. То же сделано для башен: кольца сохраняют пропорции, а поля добавляются слева и справа (или сверху и снизу).

Соотношение сторон берётся из `AvaPlot.Bounds` в `AvaPlotCanvas`, а при изменении размера окна контрол перерисовывается (подписка на `SizeChanged` в code-behind View).

### 5.3. Ханойские башни

Каждый кадр строится с нуля: основание, 3 стержня-линии, кольца и подписи A/B/C. Элементов мало (максимум ~25 при 10 кольцах), поэтому пересборка дешевле, чем обновление существующих плюмбалов на месте.

Размеры сцены фиксированы: высота стержня, положение стержней и плита основания не зависят от числа колец. При увеличении количества колец уменьшается только их толщина (`usableHeight / diskCount`), поэтому масштаб картинки не «прыгает».

Кольца рисуются не прямоугольниками, а полигонами со скруглёнными углами (`DrawRoundedRectangle` в `HanoiPlotRenderer`): у прямоугольников слишком грубый вид. Цвет — градиент от светло-голубого (маленькое кольцо) к насыщенному синему (большое), плюс затемнённая обводка для чёткости на тёмном фоне.

### 5.4. График замеров

`BenchmarkPlotRenderer` рисует на одном `Plot`:

- **измеренные точки** — зависимость среднего времени от `n`;
- **теоретическую кривую** `c·f(n)` (для перестановок `c·n!`) оранжевым пунктиром; коэффициент `c` подбирается методом наименьших квадратов и показывается в легенде;
- **легенду**, закреплённую в левом верхнем углу, чтобы она не перекрывала кривые, которые растут вправо вверх.

Цвета фона, осей, легенды и кривых берутся из текущей темы и пересчитываются при её переключении. Для графика без данных вызывается облегчённое обновление (`RefreshTheme`): перекрашиваются только оси и фон.

Подпись выбранной точки (`n` и время) показывается, пока кнопка мыши зажата, и убирается при отпускании — так она не мешает панорамированию, а зум колесом и перетаскивание остаются штатными средствами ScottPlot.

## 6. Поток данных

### 6.1. Ковёр

```
Ползунок глубины → SierpinskiSettingsViewModel.Depth
   → событие SettingsChanged
   → SierpinskiPlotViewModel.RefreshAsync()
       отменяет предыдущий запрос (CancellationTokenSource)
       пауза 90 мс (сглаживание перетаскивания)
       Task.Run → FractalRenderer.Render
       возврат в UI-поток → IFractalCanvas.Show(raster, palette)
       обновление статистики в правой панели
```

Важно: `Plot` в ScottPlot не потокобезопасен, поэтому все обращения к нему идут из UI-потока. Сама растеризация — в фоне.

### 6.2. Пошаговая отрисовка (F-10)

Если включён флажок, вместо одного кадра показываются кадры для глубин `0..n` с паузой 180 мс. Это те же данные, что и в обычном режиме, просто «проявленные» по шагам.

### 6.3. Башни

```
Кнопка/таймер → HanoiSettingsViewModel → HanoiSession.Step()
   → событие Changed(snapshot)
   → HanoiPlotViewModel → IHanoiCanvas.Show(snapshot)
   → HanoiSettingsViewModel обновляет счётчики
```

`HanoiSession` — общий объект для обеих ViewModel, поэтому визуализация и счётчики всегда согласованы.

### 6.4. Замеры

```
BenchmarkSettingsViewModel: выбор алгоритма, ExperimentConfig (максимум n, число прогонов на точку)
   → оценка длительности под настройками (обновляется при смене параметров)
   → кнопка «Запустить»
       Task.Run → BenchmarkRunner.Run(benchmark, config, progress, cancellationToken)
           для каждого n: R независимых прогонов, время каждого — Stopwatch
           в результат: среднее, минимум, максимум по прогонам
           прогресс → UI-поток
   → точки → BenchmarkChartViewModel → IBenchmarkCanvas.Show(...)
   → таблица точек в правой панели
Кнопка «Отмена» → CancellationToken → рекурсия алгоритма сама прекращает работу
```

Алгоритмы приходят в `BenchmarkSettingsViewModel` из `BenchmarkRegistry` — реестра, который наполняется через DI. Сейчас в нём зарегистрированы замеры перестановок (`PermutationsBenchmark`) и чисел Каталана (`CatalanBenchmark`); оценку длительности перед запуском считает `BenchmarkEstimator`, результаты прогона собираются в `BenchmarkSeries` из `BenchmarkPoint`, прогресс передаётся через `BenchmarkProgress`. Поэтому ни ViewModel, ни график не знают, какие именно алгоритмы существуют.

## 7. Интерфейс

`MainWindow` — сетка из трёх колонок (250 / `*` / 370). Левая колонка — `ListBox` задач (ковёр Серпинского, ханойские башни, замеры), центр и право — `ContentControl`, содержимое которых подставляется через `DataTemplate` из `App.axaml`:

| ViewModel                     | View                           |
|-------------------------------|--------------------------------|
| `SierpinskiPlotViewModel`     | `SierpinskiPlotView` (AvaPlot) |
| `SierpinskiSettingsViewModel` | `SierpinskiSettingsView`       |
| `HanoiPlotViewModel`          | `HanoiPlotView` (AvaPlot)      |
| `HanoiSettingsViewModel`      | `HanoiSettingsView`            |
| `BenchmarkChartViewModel`     | `BenchmarkChartView` (AvaPlot) |
| `BenchmarkSettingsViewModel`  | `BenchmarkSettingsView`        |

Общий контракт задач задают `ITaskViewModel` / `TaskViewModel`; задачи, которым нужна перерисовка при смене темы, реализуют `IRedrawableTask`. Строки таблицы точек в разделе замеров — `BenchmarkRow`.

Связь View ↔ ViewModel односторонняя, кроме одного места: View создаёт `AvaPlotCanvas` поверх своего `AvaPlot` и передаёт его в ViewModel через `Attach`. Так ViewModel не знает про ScottPlot и остаётся тестируемой.

Тема оформления — `ThemeVariant` приложения; кисти панелей описаны в `ResourceDictionary.ThemeDictionaries` с отдельными наборами для светлой и тёмной темы.

Графики ScottPlot тему сами не подхватывают (по умолчанию у них белый фон), поэтому:

- `AppTheme` хранит текущий режим, `ThemeService` обновляет его вместе с `ThemeVariant`;
- `AvaPlotCanvas` при создании сразу красит фон и оси — иначе до первого кадра видна белая плоскость;
- при переключении темы `MainWindowViewModel` обходит задачи, реализующие `IRedrawableTask`, и просит их перерисоваться; у графика замеров с пустыми данными вызывается `RefreshTheme` — перекрашиваются только оси и фон.

Клик по точке графика замеров обрабатывается отдельно от панорамирования: клик отличается от перетаскивания по порогу смещения мыши (4 DIP). Это позволяет одновременно сохранить штатные пан и зум и показывать подпись точки.

## 10. Подсистема замеров (как добавить новый алгоритм)

Идея взята из первой лабораторной и перенесена на интерфейсы нашего приложения:

| Слой        | Тип                                          | Роль                                                     |
|-------------|----------------------------------------------|----------------------------------------------------------|
| Domain      | `ITimedAlgorithm<TInput, TResult>`           | чистый алгоритм: `Execute(input)`, без замеров           |
| Application | `IAlgorithmBenchmark` / `AlgorithmBenchmark` | описание алгоритма + `RunOnce(n)`                        |
| Application | `AlgorithmMetadata`                          | имя, сложность, описание, диапазон n                     |
| Application | `TimedAlgorithmBenchmark<TInput, TResult>`   | адаптер «любой алгоритм → бенчмарк»                      |
| Application | `ExperimentConfig`                           | `MaxN`, шаг, число прогонов на точку                     |
| Application | `BenchmarkRunner`                            | Stopwatch, R прогонов на точку, среднее/минимум/максимум |
| Application | `BenchmarkEstimator`                         | оценка длительности замера до запуска                    |
| Application | `BenchmarkPoint` / `BenchmarkSeries`         | точка (n, среднее, min, max) и серия точек одного замера |
| Application | `BenchmarkProgress`                          | прогресс замера для UI                                   |
| Application | `TheoryFit`                                  | подбор теоретической кривой `c·f(n)`                     |
| Application | `PermutationsBenchmark`, `CatalanBenchmark`  | готовые бенчмарки перестановок и чисел Каталана          |
| Application | `BenchmarkRegistry`                          | список алгоритмов, наполняется через DI                  |
| Rendering   | `BenchmarkPlotRenderer`                      | график измерений + теоретическая кривая `c·f(n)`         |
| App         | `BenchmarkSettingsViewModel`                 | параметры, запуск, отмена, оценка длительности, таблица  |
| App         | `BenchmarkChartViewModel`                    | холст графика, выбор точки по клику                      |

Добавление нового алгоритма сводится к двум шагам:

```csharp
// 1. Алгоритм: чистый класс без знания о UI и замерах.
public sealed class MyAlgorithm : ITimedAlgorithm<int, long>
{
    public string Name => "Мой алгоритм";
    public long Execute(int n) => /* ... */;
}

// 2. Регистрация: одна запись в ServiceConfiguration.
services.AddSingleton<IAlgorithmBenchmark>(sp =>
    new TimedAlgorithmBenchmark<int, long>(
        new MyAlgorithm(),
        myMetadata,          // имя, сложность, описание, диапазон n
        n => n));            // как из n получить вход алгоритма
```

После этого алгоритм сам появляется в выпадающем списке раздела «Замеры», и для него можно построить график — ни одного нового View или ViewModel писать не нужно.

Если алгоритм рекурсивный и может работать долго, ему стоит периодически проверять `CancellationToken` (как это делает перебор перестановок), иначе кнопка «Отмена» не сможет его прервать до конца текущего прогона.

Коэффициент `c` теоретической кривой подбирается методом наименьших квадратов: `c = Σ(yᵢ·fᵢ) / Σ(fᵢ²)`. Для чисел Каталана подбирается своя теоретическая кривая, заданная в метаданных бенчмарка (<!-- TODO: указать f(n) для CatalanBenchmark -->). Если измерения лежат на кривой `n!`, линии почти совпадают — это и есть визуальное подтверждение оценки `O(n!)`.

## 11. Сохранение состояния

`AppSettings` сериализуется `JsonSettingsStore` (за интерфейсом `ISettingsStore`) в файл `%APPDATA%\AlgorithmsLab2\settings.json` и восстанавливается при запуске. Сохраняются:

- выбранная задача;
- глубина фрактала и палитра;
- число колец и скорость проигрывания башен;
- настройки замеров (в частности число прогонов на точку);
- тема (светлая/тёмная).

Каталог создаётся при первом сохранении; чтение отсутствующего и повреждённого файла покрыто тестами `JsonSettingsStoreTests`.

## 12. Утилита предпросмотра

`tools/AlgorithmsLab2.Preview` — консольная утилита разработчика. Она использует `Domain`, `Application` и `Rendering`, но не `App`, поэтому позволяет проверить геометрию и цвета без запуска интерфейса:

```
dotnet run --project tools/AlgorithmsLab2.Preview -- artifacts/preview
```

Команда сохраняет PNG с фракталами разной глубины и состояниями башен в указанный каталог.

## 13. Сборка, запуск, тесты

Требуется .NET SDK 10.0 или новее.

```
dotnet build Algorithms_lab2.sln
dotnet run --project src/AlgorithmsLab2.App
dotnet test tests/AlgorithmsLab2.Tests
```

Проект тестов использует xunit v3, поэтому, если `dotnet test` не находит тесты, их можно запустить напрямую как исполняемый файл:

```
dotnet run --project tests/AlgorithmsLab2.Tests
```

Настройки компилятора (`Nullable`, `TreatWarningsAsErrors`) заданы централизованно в `Directory.Build.props`, версии пакетов — в `Directory.Packages.props`.

## 14. Возможные расширения

- Новые фракталы: реализовать `IFractal` и добавить пункт в список задач.
- Новые замеряемые алгоритмы: реализовать `ITimedAlgorithm` и зарегистрировать бенчмарк (см. §10; по такой же схеме добавлены перестановки и числа Каталана).
- Экспорт графика в PNG: `IPlotExporter` над `Plot.SavePng`.
- Тайлинг растра для глубин ≥ 9.
